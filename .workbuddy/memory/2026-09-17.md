## API 设计 v2（用户定为只保留 GET + POST）

用户修正：**接口只保留 GET 与 POST**，"不要设老旧代码的限制"。所以 api 方案改为：

- **规则**：GET 只读（无副作用，可被浏览器预取）；POST 是唯一写入口，三种形态 —— 集合路径=新建(201)、资源路径=修改(200)、资源路径+动词=动作。动词是封闭集合 `{delete, restore}`。
- **路由 25 → 22 条**：notes 的 `PUT` + `PATCH` + `PATCH /icon` 三条合并成一条 `POST /notes/:id`（body 白名单 title/data/parent_id/icon，部分更新，用 `map[string]json.RawMessage` 判断 key 存在）；`DELETE /repos/:repo`→`POST /repos/:repo/delete`；`PUT /tags/:id`→`POST /tags/:id`；`DELETE /tags/:id`→`POST /tags/:id/delete`；`DELETE /assets/:sha`→`POST /assets/:sha/delete`；`HEAD /assets/:sha`→`GET /assets/:sha/meta`（404=不存在，顺带修掉客户端秒传时拼假 AssetMeta 的问题）；note_tags 的 add/remove 两条合并成 `POST /notes/:id/tags` body `{tag_ids:[]}` 全量设置（幂等，杀掉 409 与 FK 400）。
- **状态码**：200 / 201 / 400 / 404 / 409 / 500，**取消 204**（POST 一律回 JSON），409 只剩"标签重名"一个。
- 其余与前一轮一致：`api.Register(r gin.IRouter, s, a)` engine 归 main（P0 顺带修）、`respond.go` 的 `fail/failMsg/bind` 不再回显 SQL 原文、同包合并 `scanNotes`/`fetchNote`→`scanNote`、不抽 repo 层、不加 `/api/v1`。
- **客户端溢出范围**：只动 `client/src/api.ts`（整体重写）+ `Workspace.vue` 6 处 + `NoteEditor.vue` 1 处；`useNotes/useTags/useAssets/useRepos`、`AssetPanel`、`TrashPanel`、`SearchPanel` 零改动 —— 因为方法名收敛在 api.ts 内。
