# 对象

JSON 字段 snake_case。

| 对象        | 形状                                                                                |
| ----------- | ----------------------------------------------------------------------------------- |
| `Repo`      | `{ id, name, date }`                                                                |
| `Note`      | `{ id, parent_id, title, content, created_at, updated_at, deleted_at, tags, icon }` |
| `AssetMeta` | `{ id, name, mime, size, date }`                                                    |

## 默认值与规范化

- 创建笔记时未给的字段取默认值：`title` / `content` 空串，`parent_id` 根，`tags` `[]`，`icon` null；`created_at` 与 `updated_at` 都取当前时间。
- `Note.tags` 恒为数组，无标签是 `[]`（不是 null）。写入前规范化：trim、丢空串、去重。
- `AssetMeta.id` 是 sha256；`name` / `mime` 是**上传时**的记录，与文件内容无关 —— 同一份内容换个名字上传两次只存一份，秒传时这两个字段保持第一次的值。

## Repo

`id` 由服务端生成 UUID，同时是磁盘目录名，**不可变**；改名只改 `repos.json`，目录与既有链接不动。

`repos.json` 只是索引，**目录才是真相源**：启动时双向对账 —— 目录有而索引无则补（名字回退「未命名」），索引有而目录无则丢弃。

## 行为语义

- **`created_at` 不因编辑而变。**
- **`updated_at` 只在 `title` / `content` / `tags` 变更时刷新。** `parent_id`（移动）与 `icon`（换图标）**不刷新** —— 它们是结构与展示层面的动作，否则在按 `updated_at` 排序的视图里拖一下笔记就会跳位，而用户并不认为自己改了这篇笔记。
- **软删递归**：删一个节点会连同整棵子树标 `deleted_at`；对已删节点重复软删返回 404。标签是行内数据，跟着隐身、还原时原样回来。
- **还原递归**：还原该节点及整棵子树；若原父节点仍在回收站，该节点挂到根 —— 避免「父在回收站、子在树里」的悬空状态。
- **移动防环**：沿 `parent_id` 链向上检测，移到自身或后代返回 400。

## 标签不是实体

标签只是 `notes.tags` 里的字符串，**没有标签表，标签没有 id**。由此推出：

- **没有「新建标签」这个操作** —— 给某篇笔记写上这个字符串就是创建。
- **标签列表是派生的**（扫全部未删笔记的 `tags` 去重），所以没有任何笔记在用的标签**根本不存在**。
- **改名 / 删除是全表改写**，受影响笔记的 `updated_at` 一起刷新。
- 跨仓库不共享：每个 `data.db` 有自己的标签集合。

## 附件状态机

`status` 三态，只有 `ready` 对外可见，另两个是崩溃恢复用的中间态：

```
上传：插入 uploading ──> 写完文件并原子 rename ──> ready
                          └─ 校验失败 ──> 删文件 + 删行（回滚到不存在）
删除：ready ──> deleting ──> 删文件 + 删行
启动：Reconcile 逐仓库对账 —— 清孤儿 tmp；uploading 但文件已就位则置 ready；deleting 则重删文件并清行
```

上传是幂等的：该 sha 已经 `ready` 就直接返回已有元数据，一个字节都不传。
